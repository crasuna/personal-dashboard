# 维护者：安全发布，不上传日常记录

仓库只放源代码、通用说明和虚构测试。下载安装包作为 GitHub Release 附件。

## 一个目录开发和日常使用

**直接在正在使用的项目目录管理 Git，不需要另维护一份发布源码。** `data/`、本机凭据、备份和签名文件继续留在本地；Git 只跟踪审核过的源码。

首次克隆后启用提交检查（钩子设置不会随 `git clone` 自动复制）：

```bash
git config core.hooksPath .githooks
```

日常修改后的提交与推送：

```bash
git status
git add .
python3 tools/check_release.py --staged
git diff --cached --stat
git commit -m "说明本次修改"
git push
```

本仓库的 `.gitignore` 排除运行数据、导出 JSON、备份、凭据、APK 和密钥；仅保留两个 npm 源码清单 JSON。提交钩子还会检查**实际暂存的文件内容**，拒绝清单外文件与常见密钥。即使误用 `git add -f`，正常提交仍会被拦截；不要用 `--no-verify` 绕过它。

新增源文件需要先检查，再更新 `tools/release-files.txt`。若误暂存了私人文件，用 `git restore --staged -- 文件路径` 撤出暂存区，**不要删除本地数据**。不要对正在使用的项目执行 `git clean -fdx`，它会删除包括数据在内的忽略文件。

本机旧的 WSL 桌面启动脚本、个性化说明也不入库。已在使用的 `start.sh` 可继续作为 WSL 入口；通用桌面启动器是 `launch.py`。

推送代码不会自动生成新安装包；更新下载版本时，再按下方流程打包并创建新的 Release。不要覆盖已经发布的旧版本附件。

## 永远不要提交

- `data/`：真实数据库、同步凭据、自动备份、日志。
- 任意导出的 JSON / CSV、恢复文件、个人截图。
- `android/signing/`、`*.jks`、密钥密码文件、`*.pem`。
- `.env`、GitHub Token、第三方应用密码。
- 带真实记录的测试目录、整个个人运行目录或旧 `.git` 历史。

`.gitignore` 只是第一层保护，**不能移除已经提交过的秘密**。若凭据已经泄露，应立即撤销/更换，并按 GitHub 官方流程处理历史，不要只删除当前文件后继续使用旧密码。

## 发布前检查

```bash
python3 tools/check_release.py
git add .
python3 tools/check_release.py --staged
git diff --cached --stat
```

扫描检查 `tools/release-files.txt` 中逐项列出的源码、运行时路径、典型密钥格式和个人目录；`--staged` 还要求 Git 暂存区与清单完全一致。工作区其他文件不会被打包。它不能证明任意文字都不敏感，仍需人工审查；不要把真实记录用于截图或示例。新增源文件时需要人工检查后更新清单。

可选本地提交钩子：`git config core.hooksPath .githooks`。

## 安装包

```bash
python3 tools/package_release.py --output ../release-artifacts \
  --apk /path/to/verified-personal-dashboard.apk
```

打包工具只使用源文件清单，不递归复制整个工作目录；APK 必须与当前共享前端一致，内部不允许出现数据库/凭据/签名私钥。桌面 ZIP 和安卓 ZIP 均附带使用说明与第三方许可。

运行测试、检查解压后的初始数据为空，再把输出 ZIP 与 SHA256SUMS 上传到 GitHub Release。签名证书的公钥属于 APK 的正常组成部分，**签名私钥绝不上传**。

首次公开仓库应从干净文件创建全新 Git 历史，提交邮箱使用 GitHub 的 noreply 地址，不沿用个人邮箱。
